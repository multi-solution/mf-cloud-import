# 記帳の実行

**`skills/mf-cloud-import/SKILL.md` の手順に厳密に従うこと。** ここでは入口の流れだけを示す。

## 開始前に必ず確認する

1. `.mf-cloud/config.json` を読む。無ければ `/mf-cloud-import:mf-setup` を案内して**ここで終了**
2. `preflight.py` を実行（config に `creds_path` があれば `--creds` を付ける）。
   `expired` なら**ここで停止**し、再認可を案内する
3. **事業者の三点突合**：config の `office_name` ＝ `mfc_ca_currentOffice` の name ＝
   preflight の `office_name`。**1つでも不一致なら停止。** MCP（記帳先）とREST（証憑の
   添付先）は別々の認可のため、別事業者を向いたままエラーなく動いてしまうことがある
4. 対象フォルダを確認する（指定がなければ尋ねる）

**スクリプトのパス**：同梱スクリプトはプラグインのインストール先の `scripts/` にある。
`${CLAUDE_PLUGIN_ROOT}/scripts/...` で参照し、この変数が未定義の環境では
このコマンドファイルが置かれたプラグインのディレクトリを特定して**絶対パスで**実行する。
（カレントディレクトリは利用者の証憑フォルダなので、相対パスでは見つからない）

## 流れ

```
① ledger.py check        記帳済みの証憑を除外する（★最初にやる）
                         --ledger は config.json と同じ .mf-cloud/ledger.json を明示指定。
                         出力の ledger / ledger_exists / warning を必ず確認する
② 証憑を1枚ずつ読む      30ファイルまで。並列委譲は禁止
③ 未仕訳の明細を取得
④ 突合                   金額完全一致＋日付±7日＋名前一致が揃った1件だけ自動確定
⑤ 売掛金の回収を除外     getJournals(is_realized:false) と照合し、該当は画面の「実現」へ回す
⑥ 承認テーブルを提示     ★ここで必ず止まる
   ↓ 利用者が「実行」と答えたら
⑦ 記帳 → その場で ledger.py record   ★1件成功するごとに即登録。添付を待たない
⑧ 証憑を添付             journal_id 取得 → attach_voucher.py（config に creds_path が
                         あれば --creds を付ける）
⑨ ledger.py record --voucher-attached --force   添付フラグを更新
⑩ 完了報告
```

**⑦で即登録する理由**：⑦と登録の間でセッションが落ちると、明細のない領収書
（postJournals経由）は次回また未記帳と判定され、**二重計上する**。この窓を最小にする。

## 承認テーブルの出し方

**除外したものも必ず載せる。** 黙って飛ばさない。

### `beginner`

```
これから記帳します。内容をご確認ください。

■ 記帳するもの（7件・合計 ◯◯円）
  7/21  ◯◯デザイン    88,000円
        経費の種類：外注費 ／ 消費税10%あり ／ 領収書あり ✅

■ 今回は記帳しないもの（5件）
  ・領収書がまだ手元にないもの 4件
    （◯◯・△△…）→ 領収書が届いたら記帳します
  ・入金の消し込み 1件 → MFの画面で操作が必要です

上記7件を記帳してよろしいですか？
```

### `expert`

```
記帳 7件 / 除外 5件

 日付   借方              貸方            金額   税区分  ｲﾝﾎﾞｲｽ 証憑
 07/21  外注工賃          未払金〈カードA〉 88,000 課仕10% 適格   ✓
 ...

 除外: 証憑未着 4（◯◯ 他）/ 売掛金回収 1（画面の実現へ）

実行しますか？
```

## `tax_review` が `on` のとき

承認テーブルを作った直後、**判断が分かれる項目だけ**を `tax-reviewer` エージェントに渡す。

対象になるのは、たとえば次のようなもの。

- 1件で複数科目にまたがる可能性があるもの（車検、保険と税金が混在する請求書など）
- 資産計上の基準額を超える物品・ソフト
- 飲食で金額基準の境界にあるもの
- 事業とプライベートが混ざりうる支出
- 実入金額が請求額より少ない入金（源泉徴収の疑い）

**全件を渡さない。** 定型的に判定できたものはそのまま通す（トークンと時間の無駄になるため）。

`tax_review` が `off` のときはエージェントを起動せず、
**該当項目に印だけ付けて事実を提示する**（確認を促す文言は出さない）。

## 完了報告に必ず含めるもの

- 記帳した件数・仕訳番号・科目別の集計
- 証憑を添付した件数
- **証憑待ちで見送った件数と、その内訳**
- **除外した件数と理由**
- 要確認として残った項目
- **利用者側で操作が必要なもの**（画面での「実現」など）を最後にまとめる

## やってはいけないこと

- 承認前に登録系のツールを呼ぶ
- 証憑のない経費を「過去に実績があるから」という理由で登録する
- 売掛金の回収をAPIで仕訳する
- `ledger.py record` を省略する
- 突合できなかったものを黙って飛ばす
